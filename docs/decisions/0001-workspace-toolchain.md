# ADR 0001: Workspace toolchain pins

- **Status:** Accepted
- **Date:** 2026-08-04
- **Sprint:** 0
- **Subtask:** 0.3

## Context

The Technical Specification requires a pnpm workspace, one root lockfile, Node 24
LTS, a pinned package-manager version, conventional hoisted `node_modules` for
Electron Forge compatibility, and no additional monorepo orchestrator.

Exact versions and the minimum package-shell structure were not yet recorded in
the repository.

## Decision

- Pin Node `24.18.0` in `.node-version` and the root `engines` field.
- Pin pnpm `11.4.0` in `packageManager` and the root `engines` field.
- Use `pnpm-workspace.yaml` with `apps/*` and `packages/*` workspace patterns.
- Use `node-linker=hoisted` in `.npmrc` as required by the Technical
  Specification, and mirror it as `nodeLinker: hoisted` in
  `pnpm-workspace.yaml`, where pnpm 11 reads non-registry project settings.
- Commit one root `pnpm-lock.yaml` generated by the pinned toolchain.
- Create minimal private `@showflow/*` manifests for the eight packages named in
  the Technical Specification.
- Keep package dependency direction and automated boundary enforcement in
  Subtask 0.7 rather than inventing dependencies in the workspace scaffold.

## Consequences

- Contributors and CI must use the pinned Node and pnpm versions.
- Toolchain upgrades are explicit repository changes that update the pins,
  lockfile, documentation, and this decision record or a superseding ADR.
- The workspace remains understandable without Turborepo, Nx, Rush, or another
  orchestration layer.
- Electron scaffolding, application scripts, TypeScript package configurations,
  linting, formatting, and tests remain assigned to their later Sprint 0 subtasks.

## Electron Forge compatibility decision

Stable Electron Forge `7.11.2` depends on `@electron/rebuild@3.7.2`, which pins
`@electron/node-gyp` to an exact commit in Electron's GitHub organization. pnpm
11 blocks exotic transitive sources by default and provides only a workspace-wide
boolean for this resolution rule.

The project owner explicitly approved `blockExoticSubdeps: false` on 2026-08-04
so the specified stable Forge toolchain can install. The lockfile remains the
reviewed source of exact dependency resolutions. Lifecycle scripts remain
deny-by-default: `allowBuilds` permits Electron's binary download and
`electron-winstaller`'s host-architecture selection for its bundled 7-Zip
executable. Both are required by the pinned Forge packaging toolchain.
